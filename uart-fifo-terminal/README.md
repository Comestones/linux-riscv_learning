# Cardputer-Adv 与 FPGA 串口采集终端

做一台可以脱离电脑操作的终端。FPGA 侧用同步 FIFO 暂存采样，Cardputer-Adv 持续接收串口日志，同时允许按键读取硬件状态。先用 Windows 串口模拟器提供可重复的输入，拿到电平匹配的板卡后，再把同一组查询发给 FPGA。

## 学习顺序与交付

| 阶段 | 对应能力 | 怎样验收 |
| --- | --- | --- |
| 1 · 终端与模拟对端 | MCU 软件。练 C 外设读写、任务阻塞、队列传递、过载和超时恢复。 | 单任务版和双任务版接收相同的 6000 行，比较序号缺口和按键延迟。关掉对端后能超时，恢复后能再次查询。见 [FreeRTOS 六周实验](learn-freertos.md)。 |
| 2 · 实现外设 | FPGA 开发。把计数器、FIFO、状态寄存器和 UART 应答接起来。 | XSim 检查已知输入对应的计数和状态。实现后记录时钟约束、时序与资源，有板时从 ADV 读回真实 build ID。见 [FPGA 设计与上板](fpga-uart-fifo.md)。 |
| 3 · 检查规格 | 数字 IC 验证。写参考模型、断言和回归，找出遗漏的边界。 | 故意改错一次 FIFO 指针回绕，让用例指出第一笔不一致的数据，再用同一种子确认修复。见 [FIFO 验证](fifo-verification.md)。 |

目前三项均为待做实验。六个学习周按共同的时间预算安排，每次验收一个结果。偏嵌入式时深入驱动故障，偏 FPGA 时做到板上采样，偏验证时优先完善回归和覆盖率。

## 串口和寄存器约定

以下是第一版的设计约定，供 Windows 模拟器、ADV 固件和 FPGA 测试共用。串口设为 115200、8N1、无流控。每条命令或回复占一行，接收端接受 LF 和 CRLF。终端同一时间只发起一次查询。

| 命令或消息 | 第一版格式 | 数据含义 |
| --- | --- | --- |
| 查询版本 | `id` → `OK id <build_id>` | 标识当前固件模拟的版本或 FPGA 实际构建的版本，实验记录另记对端类型。 |
| 查询状态 | `stat` → `OK stat <empty> <full> <overflow>` | 三个字段按顺序取 0 或 1，在处理查询时取同一份状态快照。被拒绝的写入置位溢出标志，复位清零。 |
| 查询计数 | `cnt` → `OK cnt <n>` | 自复位以来 FPGA FIFO 实际接受的样本数，32 位无符号计数，串口按十进制返回。 |
| 日志与错误 | `SEQ 000000`、`ERR cmd` | `SEQ` 后的序号供终端检查漏行与重复。未知命令回复 `ERR cmd`。 |

**FIFO 第一版采用单时钟，按时钟沿前的满空状态决定是否接受请求。** 每个写请求代表一个采样。满时同拍读写只接受读，空时同拍读写只接受写，中间水位同拍读写都接受，先入先出。复位清空 FIFO、累计计数和溢出标志。输出端暂停时保留队首数据，恢复后继续按序传输。

联调时同时保存模拟器实际发送的行数、ADV 实际接收的序号以及 FPGA 的 `cnt`。三个数的统计位置不同，出现差异时可据此查明数据在哪一段丢失。后续接入 X10 的 MAC 帧计数单独核对。见 [X10 端口与计数实验](../ethernet-x10/udp-verification.md)。
