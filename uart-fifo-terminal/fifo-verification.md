# 同步 FIFO 的自检、回归与覆盖

先从[外设规格](README.md#串口和寄存器约定)列出每一拍哪些读写会被接受，再写激励。下表是验证计划，结果待实测填入。

| 场景 | 激励 | 自动检查 |
| --- | --- | --- |
| 复位与空读 | FIFO 中已有数据时复位，随后请求读取 | 占用量、累计计数及溢出标志归零，旧数据不再被读出。 |
| 满时再写 | 填满后再送一个写请求 | 占用量和累计接收数保持原值，溢出标志置位，原有数据仍按序读出。 |
| 同拍读写 | 分别在空、中间水位、满时同时提出请求 | 逐拍核对实际接受的操作，尤其检查满时读出的旧队首和下一拍可用的空间。 |
| 暂停与指针回绕 | 下游暂停数拍后恢复，多轮写入并读出递增样本 | 暂停时有效数据稳定。读出序列与参考队列一致，跨越指针边界仍无重复或遗漏。 |

## 怎样让测试抓住指针错误

1. 先在 XSim 写定向 SystemVerilog 测试。监视器在时钟沿采样请求与输出握手，参考模型按规格和自己的队列长度推算哪些请求应被接受。scoreboard 比较接受标志、数据顺序及计数，失败时打印周期、期望值和实际值。
2. 加 SVA 检查，例如在未复位的暂停周期后，输出有效信号与数据应保持稳定。记录“拍前占用量为空／中间／满 × 同拍读写”功能覆盖点，再看代码覆盖里未执行的指针回绕分支。Python 侧也可用 cocotb 和独立队列练习同一套比对。[cocotb 入门示例](https://docs.cocotb.org/en/stable/first_steps.html)
3. 用脚本在 Linux 批量跑定向和随机用例，每个失败保存种子、首错周期、日志和波形。故意把回绕条件改错一拍，记录哪个用例先失败、旧用例为何漏掉。修复后用原种子重跑，再执行完整回归。

投数字 IC 验证岗时，继续对照 OpenTitan UART 的 testplan、monitor、`uart_scoreboard` 和 FIFO 水位覆盖，把一组已验证的用例整理为可复用的 UVM 组件。跑上游完整环境前核对其支持的仿真器。[OpenTitan UART 验证环境](https://opentitan.org/book/hw/ip/uart/dv/index.html) · [仿真器与运行流程](https://opentitan.org/book/doc/getting_started/setup_dv.html)
